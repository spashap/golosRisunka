# OAuth-токен Яндекса: пошагово

Один токен на две задачи: **Метрика** (завести цели, читать отчёты) и **Вебмастер**
(поисковые запросы, показы, позиции). Делается один раз, занимает ~7 минут.

Токен — это пароль. Не вставляйте его в переписку, скриншоты и в git: он живёт
только в `.env` (файл в `.gitignore`).

---

## Часть 1. Создать приложение (5 минут)

Войдите в Яндекс **тем аккаунтом, в котором подтверждён сайт в Вебмастере**
(желательно тем же, где счётчик Метрики).

1. Откройте <https://oauth.yandex.ru/client/new>
2. **Название сервиса**: `golosrisunka-analytics` (любое — видно только вам).
3. **Для каких платформ**: отметьте **«Веб-сервисы»**.
   В поле *Redirect URI* нажмите **«Подставить URL для отладки»** — подставится
   `https://oauth.yandex.ru/verification_code`.
   Это и есть приём, который позволяет получить токен без своего сервера.
4. **Доступ к данным** — в поиске по правам найдите и отметьте четыре пункта:

   | Сервис | Право | Зачем |
   |---|---|---|
   | Яндекс.Метрика | Получение статистики, чтение параметров | читать отчёты |
   | Яндекс.Метрика | Управление счётчиками (запись) | **создать цели** |
   | Яндекс.Вебмастер | `webmaster:hostinfo` | запросы, показы, позиции |
   | Яндекс.Вебмастер | `webmaster:verify` | требуется API Вебмастера |

   Если пункта «Управление счётчиками» нет — значит выбран не тот сервис в списке;
   права Метрики лежат отдельным блоком, их два.
5. Укажите почту для связи и нажмите **«Создать приложение»**.
6. Скопируйте **ClientID** со страницы приложения.

## Часть 2. Получить токен (1 минута)

7. Откройте в браузере, подставив свой ClientID:

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID
   ```

8. Нажмите **«Разрешить»**.
9. Вас перебросит на страницу `https://oauth.yandex.ru/verification_code`, и **в адресной
   строке после решётки** будет токен:

   ```
   ...verification_code#access_token=y0_AgAAAA...&expires_in=31536000&token_type=bearer
   ```

   Нужное значение — то, что между `access_token=` и `&`. Обычно оно и на самой
   странице показано крупно.

## Часть 3. Положить в `.env` и проверить

10. В `C:\projects\GolosRisunka\.env` (локально) и в `/var/www/golosrisunka/.env`
    (на сервере) добавьте строки:

    ```
    YANDEX_OAUTH_TOKEN=y0_AgAAAA...
    YANDEX_WEBMASTER_HOST_ID=
    ```

11. Запустите проверку — она ничего не меняет, только читает:

    ```
    venv\Scripts\python.exe scripts\yandex_token_check.py
    ```

12. Скрипт напечатает `YANDEX_WEBMASTER_HOST_ID=https:golosrisunka.ru:443` — впишите
    это значение во вторую строку `.env`. После правки серверного `.env` нужен
    `./restart.sh` (не `deploy.sh` — код не менялся).

13. Когда проверка зелёная, заводим цели в Метрике:

    ```
    venv\Scripts\python.exe scripts\metrika_goals_sync.py --dry-run   # посмотреть
    venv\Scripts\python.exe scripts\metrika_goals_sync.py             # создать
    ```

## Что может пойти не так

**`HTTP 403` на Метрике.** Счётчик принадлежит не вам (мог завести подрядчик).
Нужен доступ к счётчику 109824945 уровня **«Полный доступ»** — «Только просмотр»
хватает на чтение отчётов, но НЕ на создание целей.

**`HTTP 403` на Вебмастере.** В токене нет `webmaster:hostinfo`. Часть 2 заново
(приложение пересоздавать не нужно — добавьте право и перевыпустите токен).

**Сайт не найден в списке хостов.** Сайт не добавлен/не подтверждён в Вебмастере
именно этим аккаунтом.

**Токен перестал работать через полгода-год.** Так и задумано: у токена есть срок
(`expires_in` в адресной строке — секунды). Повторите Часть 2, приложение остаётся.
Признак — `HTTP 401` в проверке.

## Отдельно: реклама ведётся подрядчиком

Директ у фрилансера, доступа к нему нет — значит **расход и CPA по кампаниям из
Метрики не придут**: они появляются только если рекламный аккаунт СВЯЗАН со счётчиком.
Проверка (`yandex_token_check.py`) прямо скажет, есть связка или нет.

Что от этого меняется:

* **Что мы измеряем сами, без чьей-либо помощи.** Директ дописывает к ссылке `yclid` —
  мы его сохраняем в визите. Значит «этот визит из рекламы → этот заказ → эти деньги»
  считается на нашей стороне и НЕ зависит от отчётности подрядчика. Это, собственно,
  единственная независимая проверка его работы.
* **Чего без подрядчика не будет.** Имя кампании (без UTM или без связки со счётчиком
  `yclid` говорит только «это Директ», но не «какая кампания») и расход.

**Сообщение подрядчику — можно переслать как есть:**

> Привет! Три просьбы по аналитике, каждая на пару минут:
> 1. Свяжите рекламный аккаунт со счётчиком Метрики **109824945** (в кампании:
>    Метрика → номера счётчиков). Без этого в Метрике нет расхода и CPA по кампаниям.
> 2. Проверьте, что включена **разметка ссылок для Метрики** (yclid).
> 3. Разметьте объявления UTM: `utm_source=yandex`, `utm_medium=cpc`,
>    `utm_campaign={campaign_name}`, `utm_content={ad_id}`, `utm_term={keyword}` —
>    тогда названия кампаний видны в нашей аналитике напрямую.
>
> И скажите, пожалуйста, на какие цели Метрики настроены стратегии — мы завели
> нормальный набор целей, и часть из них лучше подходит для обучения, чем «покупка»
> (её пока слишком мало для статистики).
